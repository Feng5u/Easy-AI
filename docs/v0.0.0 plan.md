## 0. 给 Codex 的执行契约

实现一个本地桌面应用：学生在三个标签页中拼接积木，软件生成可阅读的标准 PyTorch 代码，在本地或 SSH 服务器的现有 Python / conda 环境中真正执行，实时显示训练日志、指标和图像，并将结果与源积木关联。

本版本的主验收案例是原文中的 MNIST CNN。目标是**计算语义等价与真实运行闭环**，不要求生成文本逐字复制示例。不要将 MNIST 脚本写死后仅用积木修改几个参数，也不要用假日志、预制曲线或模拟训练替代真实执行。

执行规则：

1. 先读当前仓库、`AGENTS.md`（若已存在）、原 v0.0.0 和本文。实际 HEAD 不等于上述基线时，先检查差异；保留已有实现，不重建覆盖，不回退提交。将差异与采用的处理记入 `docs/implementation-progress.md`。
2. 按第 18 节的里程碑依次推进。先完成“编译器 → 本地真实训练”的纵向闭环，再补全界面和 SSH。每阶段完成后运行对应测试、记录结果，再进入下一阶段。
3. 原需求中的冲突按第 1 节的明确裁决执行。这些是本文新增的实施决策，不要误称原文已经规定。未明确的低风险细节采用最小、可逆实现，并记录理由。
4. 不新增登录、云端账户、计费、多人协作、插件市场、任意 Python 编辑执行、分布式训练、超参数搜索或 LLM 助教。不要为了“可扩展”引入微服务、Redis、Celery、Kubernetes 或远程常驻 Web 服务。
5. 编译器和运行协议先建立测试。不得为使测试通过而关闭类型检查、吞掉异常、放宽路径检查，或把真实集成测试改成模拟实现。
6. 编码期间可以用测试替身；正式运行入口必须调用真实 Runner。测试替身只能存在于测试目录或明确的开发环境依赖注入中。
7. 新增依赖须有用途说明并提交锁文件。不要使用浮动 `latest` 作为可复现构建依据。本文没有冒充验证过一组精确依赖版本，版本冻结是 M0 的交付物。
8. 不擅自提交凭据、修改服务器共享环境、下载数据、覆盖已有项目或删除运行结果。开发任务本身不授权发布版本、推送主分支、创建云资源或向服务器执行破坏性操作。
9. 每阶段报告：完成任务 ID、修改文件、执行命令、真实测试结果、未通过项、下一阶段。没有运行的测试写“未运行及原因”，不可写成“通过”。

## 1. 范围与原文歧义裁决

### 1.1 保留的产品边界

保留 Electron + React + Blockly + FastAPI + Paramiko + subprocess 技术栈；保留“模型 / 数据处理 / 训练管线”三个工作区；保留 PyTorch 代码对照、注册对象引用、SSH 配置、包组管理、Tutorial、图表配置和产物映射。[R1][R2]

### 1.2 必须采用的实施裁决

| ID | 原文情况 | 本计划的明确执行规则 |
| --- | --- | --- |
| D01 | 每类只允许注册一个，但示例有训练和测试各一套 Dataset / DataLoader | 一个项目最多注册 1 个活动模型类、1 个训练 Dataset、1 个测试 Dataset、1 个训练 DataLoader、1 个测试 DataLoader；是“每个角色一个”，不是 Dataset 总共一个。允许存在未注册草稿。 |

| D03 | 模型区输出模型类，训练参数写 `model_ref` | 跨标签页引用模型定义的稳定 ID；编译器在训练作用域自动生成一次模型实例并 `.to(device)`。界面写“使用模型”，不要求学生再拼实例化积木。 |

| D06 | 训练容器只有“每轮结束后”，示例还要求训练前样本和训练后预测图 | 以 `train.loop` 作为唯一训练管线根；保留 `body` 表示每轮结束后，新增 `before`、`after` 两个可视化槽。禁止将全部可视化无条件放到脚本末尾。 |

| D08 | DataLoader 示例写死 `num_workers=2, pin_memory=True` | 工程参数不做学生积木：Linux 默认 workers=2，其余平台默认 0；只有 CUDA 启用 pin_memory。设置写进运行快照并展示实际值。开发/测试可显式统一 workers=0。[T4] |
| D09 | 训练示例使用 `plt.show()`，但要在远程无桌面环境运行 | 正式运行用 Agg 后端写 PNG；前端显示文件，不运行阻塞式 `plt.show()`；每次渲染后关闭 figure。[T5] |
| D10 | 示例只展示 MNIST，但积木选项包含 CIFAR10、FashionMNIST | 保留并实现 3 种 Dataset 适配器；MNIST 是全链路主验收。CIFAR10 输入通道、尺寸和 Normalize 参数必须随数据配置验证，不能套用 MNIST 的 `1568`。 |
| D11 | `viz.savefig` 没定义属于哪张图 | 增加 `viz.figure.save` 槽，最多一个 `viz.savefig`；必须从所属 figure 获取引用，禁止依赖 pyplot 的“当前图”。 |
| D12 | “完整 PyTorch 代码”与日志采集存在潜在冲突 | 学习代码中的模型、训练和测试循环保持展开；协议、取消检查与文件写入可引用同目录的标准库辅助文件。导出整个运行代码目录，无需安装 Easy-AI Python 包即可运行。 |
| D13 | 模型体既能放层也能放 Sequential，未定义 forward | 按 body 的连接顺序依次执行；Sequential 生成子模块，Flatten 生成一次张量展平。v0.0.0 不支持分支、残差、多个输入或自动修补尺寸。 |

## 2. 主验收流程与界面行为

### 2.1 学生的完整路径

启动软件 → 创建或打开项目 → 选择“本机”或“学校服务器” → 检查 Python 环境和数据位置 → 从 MNIST 示例或空白项目开始 → 在数据页建立预处理、训练/测试 Dataset、训练/测试 DataLoader → 在模型页建立 CNN 并注册 → 在训练页引用这些对象并设置训练参数 → 配置训练前、每轮结束后、训练后的图像 → 运行检查 → 开始训练 → 查看真实日志、指标、图像 → 点击输出定位积木 → 保存、关闭、重新打开查看历史运行。

界面默认隐藏代码面板；用户打开后显示当前工程的生成代码。只读，不提供任意 Python 编辑执行。点击积木不能隐式启动训练；只在选中训练根时显示明确的“运行这个训练管线”按钮。

### 2.2 主窗口布局

顶部：项目名、保存状态、运行位置与环境、检查、运行、停止、代码开关。

主体：左侧积木分类；中间三个标签页的工作区；右侧所选积木说明与参数面板。选择画布积木时，右侧显示 PPT 式图表配置网格。代码面板作为可折叠区域，不永久挤占画布。

底部：运行记录、终端日志、指标、图像、文件、问题列表。日志是只读查看器，不是可以输入任意命令的终端模拟器。

首次使用的字段采用“服务器地址”“账号”“数据放在哪里”等标签；高级详情中保留 SSH host、环境前缀等真实名称。错误卡片先说发生了什么，再提供“定位积木 / 修改配置 / 查看技术详情”。

### 2.3 示例工程参数

- 数据：MNIST，训练和测试分开；ToTensor → Normalize(mean=0.1307, std=0.3081)。
- 模型：Conv2d(1,16,3,padding=1) → ReLU → MaxPool2d(2) → Conv2d(16,32,3,padding=1) → ReLU → MaxPool2d(2) → Flatten → Linear(1568,128) → ReLU → Linear(128,10)。
- 训练：batch_size=128、epochs=10、SGD、learning_rate=0.01、momentum=0.9、CrossEntropyLoss。测试 loader 不打乱。
- 可视化：训练前 5 个训练样本；每轮训练损失与测试准确率；训练后 10 个测试样本的预测标签和真实标签。

这组参数来自基线案例。[R2] “快速检查”另用 1 epoch、最多 1024 个训练样本和 256 个测试样本，必须在界面、运行记录和输出中醒目标记小样本，不能修改或冒充正式示例参数。

## 3. 技术架构与进程边界

### 3.1 采用模块化单体，不采用微服务

```text
Electron Renderer
  React 页面 + 三个 Blockly workspace + 图表配置 + 只读代码查看
       │ 仅白名单 contextBridge API，不接触 fs / SSH / shell
Electron Preload
       │ 经过参数校验的 IPC
Electron Main
  原生文件选择、窗口生命周期、用户级配置、后端启动、IPC 鉴权
       │ 127.0.0.1 HTTP + Bearer token；事件用 SSE
本地 FastAPI Sidecar
  ProjectService / Compiler / EnvironmentService / RunService
       ├── LocalRunner ── subprocess ── 选定训练环境中的 Python
       └── SSHRunner ── Paramiko / SFTP ── Linux 服务器中的 Python
                                            │
                            每次运行临时上传的 supervisor + code bundle
                            不安装远程 Easy-AI，不启动远程 FastAPI
```

SSH、subprocess、环境探测和文件同步放在 Python 后端，不放在 React，也不在 Electron 与 FastAPI 两边各实现一套。

### 3.2 各层职责

| 层 | 负责 | 不允许负责 |
| --- | --- | --- |
| Renderer | 展示、Blockly 编辑、序列化、客户端友好校验 | 任意文件读写、凭据持久化、拼接 shell、实际训练 |
| Preload | 小型、类型明确的桥接接口 | 暴露原始 `ipcRenderer`、任意 channel 或 Node API |
| Electron Main | 原生对话框、路径授权、启动/关闭 sidecar、代理 API、事件转发 | 生成训练代码、实现第二个 SSH 客户端 |
| API/Service | 权威校验、保存、编译、任务管理、环境、传输 | 在 FastAPI 请求线程中直接跑 PyTorch |
| Compiler | 工程快照 → IR → Python + SourceMap + 诊断 | 网络访问、安装包、读取 SSH 凭据、执行用户代码 |
| Runner | 预检、暂存、启动、取消、拉取事件和产物 | 根据 UI 文字猜测训练逻辑 |
| Runtime bundle | 真实训练、指标上报、图像生成、监督进程 | 依赖远端安装 FastAPI / Paramiko / Easy-AI |

### 3.3 开发与分发环境

前端使用 TypeScript strict、React、Blockly、Vite、pnpm workspace；状态管理先采用 React 状态和一个小型 store，不为此引入大型框架。只读代码查看采用 Monaco，装饰器负责行背景高亮。

后端使用 Python 3.11 作为首个验证基线、FastAPI、Uvicorn、Pydantic v2、Paramiko；测试使用 pytest。桌面使用 Electron，分发使用 electron-builder；本地 sidecar 使用 PyInstaller 的目录模式打包。前端单元测试使用 Vitest，交互测试使用 Playwright。

**应用后端环境与训练环境分离。** PyInstaller 包不捆绑 torch / torchvision / conda。学生仅连接远程服务器时，不应被要求在本机安装 PyTorch 或开发工具。训练环境由用户选择或应用在明确授权后新建。

优先验收 Windows 11 x64 客户端连接 Linux SSH 服务器，同时在 Linux 做自动化集成测试。macOS 的窗口、打包和本地 MPS 路径保留实现，但只有真实测试过才可声明支持；没有设备时列为未验证，而不是伪造支持矩阵。操作系统偏好尚未由需求指定，这是本计划的初始发布顺序，不是原需求事实。

M0 必须记录所选 Node、pnpm、Electron、Blockly、Python 和核心依赖的精确版本，并验证彼此兼容。提交 `pnpm-lock.yaml` 与 Python lock；受控训练包另有独立 profile lock，不能与应用后端依赖混装。

### 3.4 桌面安全基线

Electron 显式设置 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`；不禁用 webSecurity；不加载远程可执行脚本；校验 IPC sender；用自定义协议承载应用和受控产物，不向 renderer 开放任意 `file://`。这些是 Electron 官方安全建议对应的落地约束。[T1]

Renderer 只能调用 `window.easyai.projects.*`、`compile.*`、`runs.*`、`environments.*`、`connections.*` 等固定方法。不得出现 `execute(command)`、`readFile(path)`、`request(url)` 之类不受限制的通用接口。

### 4.3 Sidecar 启动协议

Main 生成 256-bit 随机会话 token，通过匿名 stdin 管道发送给后端；不能放在命令行参数、URL、日志或项目文件中。后端只监听 `127.0.0.1`，自行 bind 端口 0 得到空闲端口，复用已绑定 socket 启动 Uvicorn，避免“先探测空闲端口再绑定”的竞争。

后端初始化后向 stdout 输出一条机器可读 ready 消息，内容仅含 port、protocolVersion、pid；应用日志写 stderr。Main 带 Bearer token 调用 health 验证后再显示工作台。所有业务接口都鉴权；不开启任意来源 CORS；FastAPI 只运行一个 worker。退出、后端崩溃、启动超时均有明确 UI 状态。

### 5.3 保存与恢复

工作区语义变更后 800ms 防抖自动保存；明确提供手动保存。保存过程为：全量序列化 → schema 校验 → 比较 expectedRevision → 写同目录临时文件 → flush / fsync → 原子替换 → 更新 revision。旧文件备份保留最近一份。并发保存只允许一个写入者，陈旧 revision 返回冲突，不执行最后写入者覆盖。

拖动位置、缩放、选择积木也可保存，但不改变 `programHash`。工程 revision 用于编辑一致性，programHash 用于执行语义一致性，不要混为一谈。

同一项目第二个窗口默认只读，使用 lock 文件或平台文件锁避免竞争。无法保存时保留未保存状态和原数据，不把“已经序列化到内存”等同“保存成功”。

打开时先解析原始 JSON、限制体积和结构深度，再检查 schema/library 版本，再预扫描所有 block type。遇到不支持的未来版本或未知块，进入可解释的只读模式，保留原始字节，不让 Blockly 加载过程静默丢块后再自动覆盖。

### 5.4 不可变运行快照

点击运行时后端从已提交工程生成快照，同时存储 programHash、生成代码 SHA-256、compilerVersion、blockLibraryVersion、实际环境与数据绑定摘要。快照写入成功后才能启动。

训练过程中允许编辑当前工程，但本次运行永远使用快照。旧运行的代码和错误必须使用旧 source-map；即使当前积木被删除，也能打开该次运行的只读快照定位。界面区分“当前工程代码”和“运行记录代码”，不得拿新版行号解释旧日志。

### 5.5 默认忽略和保留规则

开发仓库忽略本地凭据配置、真实数据、用户 runs、缓存、构建输出。示例工程本身纳入版本控制。应用不自动删除历史 runs，不递归清理老师数据目录。后续增加清理功能时再独立设计确认和保留策略。

## 6. 对象注册与跨标签页引用

### 6.1 稳定 ID，不按名字串联逻辑

每个实例使用 Blockly block.id。对能定义对象的根积木，`symbolId = block.id`，避免无必要的第二套 ID。名字只用于显示和生成 Python 标识符，引用字段保存 symbolId，不保存名字作为真实引用。

根积木的 `extraState.easyai` 保存 `version` 和 `registered` 等编辑状态；`fields.NAME` 保存 Python 名称。Dataset 的角色从 SPLIT 字段得出，DataLoader 的角色由其 Dataset 推导，不单独维护一个可能冲突的 role 字段。注册表从三个工作区重建，不另存一份可独立编辑的注册表。

```ts
export type SymbolKind =
  | "transform"
  | "dataset"
  | "dataloader"
  | "model_class";

export interface SymbolEntry {
  id: string;                         // 等于定义块 ID
  kind: SymbolKind;
  name: string;                       // Python 标识符
  role?: "train" | "test";
  workspace: "data" | "model";
  registered: boolean;
}
```

### 6.2 命名与引用校验

本版本名称限定为 ASCII Python 标识符：`[A-Za-z][A-Za-z0-9_]*`，区分大小写；禁止 Python 关键字、导入别名和保留运行名，例如 `torch`、`nn`、`transforms`、`datasets`、`device`、`model`、`optimizer`、`criterion`、`main`。通过 Python `keyword` 模块及统一保留名集合校验；不靠前端单一正则完成安全检查。

界面允许另设中文说明文字，但它不是 Python 名称。用“用于生成代码的名称，只能使用英文字母、数字和下划线，且不能以数字开头”说明规则。

每次语义变更重建注册表，并验证：名字项目内唯一、活动对象数量符合 D01/D02、引用类型相符、引用对象已注册、DataLoader 角色与训练参数相符、不能引用自身形成环。后端校验是权威结果，前端校验只为了即时反馈。

### 6.3 改名、删除、复制、恢复的精确定义

改名：只改定义的 NAME，引用仍指向同一 ID，所有下拉显示即时刷新。

删除或取消注册：引用字段保留原 ID，显示“找不到原先选择的对象”，生成 `REF_NOT_FOUND` 或 `REF_NOT_REGISTERED` 诊断并阻止运行。不能自动选中列表第一个对象。Undo 恢复原块与 ID 后，引用恢复。

复制：新块必须获得新 ID；复制的可注册定义默认未注册，名称由用户确认或生成未占用后缀。新块不能继承旧定义的注册身份。先不支持跨标签页复杂子图复制。

恢复：先从 JSON 建立所有定义的索引，再加载引用字段。使用自定义 `FieldSymbolRef`，允许暂存不存在的值并显示 tombstone；不能使用会在选项不完整时偷偷重置 value 的普通下拉实现。加载完毕后统一刷新选项并做诊断。

### 6.4 模型引用的执行语义

模型区的 `model.define` 定义类；训练区的 modelRef 指向该定义。编译器在主函数中生成 `model = <ClassName>().to(device)`。模型类名称和实例名称不同是有意设计：前者来自学生注册，后者是训练模板保留名。

v0.0.0 只运行一个活动训练根。允许保存其他未连接的草稿，但多个有效的 `train.loop` 根构成可解释的错误，要求用户删除或停用额外根，不根据坐标随机选一个。

## 7. 积木库的统一声明与 21 类积木实现

### 7.1 一份声明，三类消费者

`packages/block-library/manifest.json` 是字段、槽、类型、默认值、帮助文案、import 需求和 handler ID 的唯一声明源。前端据此创建块与参数界面；后端据此校验；测试验证声明与两侧实现一致。原文 YAML 是设计依据，不直接让用户编辑 YAML 模板执行代码。[R2]

真实代码生成器是后端可信源码中的 handler 表；项目文件不能指定 Python 模块、模板路径或 import 路径。

```json
{
  "id": "model.conv2d",
  "version": 1,
  "category": "model",
  "label": "卷积层",
  "placement": "model_node",
  "fields": {
    "IN_CHANNELS": {"type": "integer", "min": 1, "default": 1},
    "OUT_CHANNELS": {"type": "integer", "min": 1, "default": 16},
    "KERNEL_SIZE": {"type": "integer", "min": 1, "default": 3},
    "PADDING": {"type": "integer", "min": 0, "default": 1}
  },
  "inputs": {},
  "imports": ["torch.nn"],
  "backendHandler": "model.conv2d",
  "helpKey": "blocks.model.conv2d"
}
```

此处 manifest 结构是本计划规定的新格式。M1 建立 JSON Schema，未知字段报错。`backendHandler` 只能命中打包进应用的静态白名单。

### 7.2 数据处理：5 类

| ID | 输入 / 字段 | 编译语义与验证 |
| --- | --- | --- |
| `data.compose` | NAME；steps 槽；注册状态 | 生成命名的 `transforms.Compose([...])`。步骤按连接顺序，不按位置排序。至少有 ToTensor；Normalize 必须在其后；本版本最多一个 ToTensor 和一个 Normalize。 |
| `data.to_tensor` | 无 | 生成 `transforms.ToTensor()`。只能放在 compose.steps。 |
| `data.normalize` | mean、std | 支持有限实数或逗号分隔的有限实数列表；标量按输入通道重复，列表长度必须等于通道数；std 每项 > 0。只解析数值，绝不 eval。 |
| `data.dataset_builtin` | NAME；datasetName；split；transformRef；注册状态 | datasetName 白名单 MNIST/CIFAR10/FashionMNIST；split=train/test；root 来自 RunConfig 的数据根目录；`download=False`；输出对象有角色与输入元数据。 |
| `data.dataloader` | NAME；datasetRef；batchSize；shuffle；注册状态 | batchSize 正整数，UI 默认 128；角色来自 Dataset；测试 loader 默认且要求 shuffle=False；workers 与 pin_memory 由平台策略决定。 |

Normalize 的列表支持是为了原文同时列出灰度与 RGB 数据集所需的最小补充。前端把字符串解析为数值数组，后端再次严格检查 NaN、Infinity、空列表、长度和范围，不将用户文本直接拼入 Python。

### 7.3 模型：8 类

| ID | 输入 / 字段 | 编译语义与验证 |
| --- | --- | --- |
| `model.define` | NAME（类名）；body；注册状态 | 模块顶层定义 `nn.Module` 类；body 必须非空；init 建立子模块，forward 按 body 次序处理 x。 |
| `model.sequential` | layers | 生成 `nn.Sequential(...)`；允许 conv2d/linear/relu/maxpool2d/dropout；本版本不允许嵌套 Sequential 或内部 Flatten，后者放在模型 body 中。 |
| `model.conv2d` | inChannels/outChannels/kernelSize/padding | 正整数通道与 kernel，padding ≥ 0；stride=1、dilation=1、groups=1、bias=True 固定在模板配置。 |
| `model.linear` | inFeatures/outFeatures | 都是正整数；示例填 1568，不接受 `32*7*7` 这样的自由表达式。参数说明可以解释 `32×7×7=1568`。 |
| `model.relu` | 无 | 生成 `nn.ReLU()`。 |
| `model.maxpool2d` | kernelSize | 正整数；stride=kernelSize，padding=0、dilation=1、ceil_mode=False。 |
| `model.dropout` | p | 有限实数，0 ≤ p < 1；默认 0.5。 |
| `model.flatten` | 无 | 只在 model.body；生成 `x = x.view(x.size(0), -1)`；不是没有参数的 nn.Module 实例。 |

模型 body 的每个非 Flatten 项获得确定性的成员名，如 `stage_1`、`stage_2`；按 body 序号命名。原示例的 `conv` / `fc` 名称不是硬性要求，但结构和 forward 次序必须一致。

连接类型用于减少错误，但仍必须在编译器检查 placement 和输入槽。例如把损失图放进 Sequential，即使工程 JSON 被手动修改，也应在执行前拒绝。

### 7.4 训练：1 类

| ID | 输入 / 字段 | 编译语义与验证 |
| --- | --- | --- |
| `train.loop` | modelRef、trainLoaderRef、testLoaderRef、criterion、optimizer、learningRate、epochs；before/body/after | 唯一活动训练根；criterion=CrossEntropy；optimizer=SGD/Adam；learningRate 为有限正数；epochs 为正整数；before 执行一次，body 在每轮训练和测试完成后执行，after 在全部 epoch 完成后执行。 |

SGD 的 momentum 固定 0.9；Adam 使用所冻结 PyTorch 版本的标准默认配置，并把实际默认值记录进 profile / 运行元数据。不要把 SGD 的 momentum 参数传给 Adam。所有冻结的工程参数集中在 `TrainingDefaults`，不是散布在多个模板中。

运行前确认训练和测试 loader 不是同一个 ID，分别绑定 train/test 角色，并且 Dataset 类别数、输入格式一致。UI 不提供同一个训练 loader 冒充测试 loader 的快捷方式。

### 7.5 可视化：7 类

| ID | 输入 / 字段 | 编译语义与验证 |
| --- | --- | --- |
| `viz.figure` | layout；size；panels；save | layout 白名单 [1,1]/[1,2]/[2,2]/[1,3]/[2,5]；size 小/中/大；panels 数量不能超过格子数；至少一个 panel；生成独立 figure。 |
| `viz.panel` | chartType；data；style；图像网格的 count/rows/cols | chartType=line/image_grid/scatter；data 槽可串接多个 data_source；style 接受 title/legend/axis，各最多一个。 |
| `viz.data_source` | source；xSource | source 为 train_loss/test_accuracy/train_samples/test_samples/predictions；数值图的 xSource 本版本固定为 epoch；样本图不接受数值 xSource。 |
| `viz.title` | text；color | 文本长度有限制，按 Python 字符串字面量编码；color 映射 black/red/green/blue 白名单。 |
| `viz.legend` | 无 | 生成当前 panel 对应 Axes 的 legend；图像网格不启用普通曲线图例。 |
| `viz.axis` | showTicks | 作用于所属 panel 的 Axes；不使用依赖全局“当前图”的隐式状态。 |
| `viz.savefig` | path | 只允许在所属 figure.save；path 为输出目录内的相对文件名/子路径；只能 PNG；实际文件名包含 figure 标识和阶段/epoch 防止冲突。 |

`train_samples` 是对原文样本预览的最小补充。旧“训练准确率”选项规范化为 `test_accuracy` 时必须保留迁移提示。`predictions` 在 before 中不可用，编译时报“预测结果在测试完成后才会产生”；body 与 after 可用。

### 7.6 Blockly 物理结构规则

根定义块不拼接成一条执行语句链，依赖通过引用字段表达。compose.steps、model.body、sequential.layers、figure.panels、panel.data/style 使用 statement input 中的 next 链表达顺序。

读取子块时只沿对应 input 和 next 链走，不能用 `getAllBlocks()` 的返回顺序当语义顺序。禁用块及其子树不进入程序；断开的草稿保留在工程里，但给出非阻断提示，不把它们偷偷加入执行。

图表配置面板编辑的是 workspace 中真实的 figure/panel/source/style 块；它不是另一套 JSON 数据源。一次网格调整用 Blockly 事件分组，确保 Undo 能完整还原。不实现任意像素定位或复杂可视化设计器。

## 8. 编译器：工程快照到可执行代码

### 8.1 唯一权威编译路径

```text
ProjectDocument
  → 校验外壳、版本和资源限制
  → Blockly JSON Decoder
  → BlockIR（去掉坐标、颜色、缩放等 UI 信息）
  → 符号表与语义校验
  → ProgramIR（依赖顺序、模型结构、训练阶段、图表规格）
  → PythonEmitter + SourceMapBuilder
  → ast.parse / compile 语法检查（不执行）
  → CompileResult
```

编译器在 Python 后端实现。前端不另建一套 Python generator，否则会产生预览与运行代码不一致的问题。Decoder 只解释冻结 Blockly 版本实际输出的受支持结构，不在后端加载浏览器，也不接受项目内自带的执行模板。

M1 必须用 Node/headless Blockly 生成序列化 fixtures，再让 Python Decoder 读取这些真实 fixtures 做跨语言测试。尤其覆盖 inputs.block、inputs.shadow、next、禁用状态、extraState、引用字段和空 workspace；不要凭记忆假设 Blockly JSON 的字段行为。[T2]

### 8.2 IR 的最低合同

工程、API 外壳和结构化事件外壳字段使用 camelCase，Python 模型可以通过 alias 使用 snake_case；训练指标的 payload 和 CSV 列名是明确的例外，统一保留第 9.5 节的 train_loss、test_accuracy 等 snake_case，前后端不得擅自转换成另一套指标名。以下是类型合同，不是可跳过实现的注释：

```ts
export interface Origin {
  blockId: string;
  workspace: "data" | "model" | "training";
}

export interface BlockIR {
  typeId: string;
  origin: Origin;
  fields: Record<string, unknown>;    // 随后按 manifest 严格解析，不允许直接输出
  inputs: Record<string, BlockIR[]>;
}

export interface ProgramIR {
  irVersion: 1;
  symbols: SymbolEntry[];
  transforms: BlockIR[];
  datasets: BlockIR[];
  dataloaders: BlockIR[];
  model: BlockIR;
  training: BlockIR;
}

export interface Diagnostic {
  code: string;
  severity: "error" | "warning" | "info";
  message: string;
  origin?: Origin;
  field?: string;
  suggestion?: string;
  details?: Record<string, unknown>;
}

export interface SourceSpan {
  file: "train.py";
  startLine: number;                 // 1-based，包含边界
  endLine: number;
  origin: Origin;
  kind: "semantic" | "scaffold";
}

export interface CompileResult {
  revision: number;
  programHash: string;
  compilerVersion: string;
  diagnostics: Diagnostic[];
  runnable: boolean;
  code?: string;
  codeHash?: string;
  sourceMap?: SourceSpan[];
}
```

实际后端 ProgramIR 应进一步使用 TransformDef、DatasetDef、LayerSpec、TrainingSpec、FigureSpec 等带判别字段的 Pydantic 模型，杜绝 unknown 字段直接到 emitter。上面的 BlockIR 是入口通用层，不是把全部逻辑塞进字典的理由。

### 8.3 校验顺序

先做结构和类型，再做引用和数量，再做图/作用域，再做数值与受支持能力，最后做静态尺寸检查。结构坏了就不要继续产生大量误导的下游诊断。

阻断例：缺训练根、缺必填引用、重复名称、未注册引用、循环依赖、非法层 placement、std=0、NaN learningRate、epochs≤0、不支持的 loss、训练前引用预测结果、输出路径越界。

允许保存未完成工程；编译返回 `runnable=false` 和诊断。预览可展示有效片段或明确说明尚不能生成完整程序，但“运行”必须禁用。HTTP 参数错误与工程诊断分开处理，不能把未完成积木当服务器内部错误。

### 8.4 依赖与 import

从唯一活动 train.loop 出发收集 modelRef / loaderRef 的依赖闭包：loader → dataset → transform。未被活动训练引用的草稿不执行。检测环后按稳定拓扑序生成数据定义。

imports 使用白名单映射，例如：

```text
torch                   → import torch
torch.nn                → from torch import nn
torchvision.datasets    → from torchvision import datasets
torchvision.transforms  → from torchvision import transforms
matplotlib.pyplot       → import matplotlib.pyplot as plt
```

同时补齐所用脚手架的标准库 import。别名固定；按既定顺序去重；不把 `torch.nn` 简单拼成 `import torch.nn` 后又在模板里使用未定义的 `nn`。

### 8.5 代码骨架与顺序

模型类放在模块顶层，运行逻辑放在 `main()`，末尾使用 `if __name__ == "__main__":`。这是为不同平台的进程启动与 DataLoader 兼容而对原文线性代码顺序做的结构化调整，计算依赖不变。[T4][T9]

```python
# 以下仅展示结构，具体语句由 emitter 根据 ProgramIR 输出。
import torch
from torch import nn
from torchvision import datasets, transforms
from easyai_runtime import RunContext


class MnistCNN(nn.Module):
    def __init__(self):
        super().__init__()
        # 各层与 Sequential 在这里逐条展开。

    def forward(self, x):
        # 每个模型 body 节点分别输出计算语句。
        return x


def main():
    context = RunContext.from_cli()
    # 1. 设置 seed、选择 device。
    # 2. 使用实际 data_root 创建 transform / dataset / dataloader。
    # 3. 实例化模型、loss、optimizer。
    # 4. 执行 before 图表。
    # 5. 展开的 epoch / batch / eval 循环，每轮执行 body 图表。
    # 6. 执行 after 图表，保存最终 state_dict，输出 summary。

```

不能把完整训练主体封装成不可见的 `context.train_model(config)`；学生必须能在 train.py 看到 `.train()`、`.eval()`、`zero_grad()`、`backward()`、`step()`、`no_grad()` 和指标计算。

导出代码目录必须包含 train.py 引用的辅助文件、环境说明与运行命令。单独只导出 train.py 却遗漏 `easyai_runtime.py` 不算完成“可运行代码导出”。

### 8.6 字符串与路径编码

标识符只取经验证的符号名；数值只取经验证的 Python int/float；文字用安全字符串字面量编码，例如 `repr(value)`；输出路径不直接插入 shell。模板中禁止通用 `eval` / `exec`。编译器可以用 `ast.parse` / `compile` 检查语法，但绝不能执行生成代码验证正确性。

生成器使用逐行 emitter 而非生成之后正则匹配块文本。`emit_line(text, origin, kind)` 每输出一行即记录源信息。需要格式化时必须在行号收集前完成，或在格式化后重新建立真实映射；不能对已经映射的代码再跑 formatter 改行号。

### 8.7 一个积木映射多个代码区间

例如 Conv2d 的构造出现在 `__init__`，所在模块的调用出现在 forward；模型定义块还覆盖类声明和脚手架。SourceMap 必须支持同一 blockId 对应多个 span，不能用单一 start/end 把整份代码涂亮。

点击积木：查当前编译结果的所有 span，滚动到首个 semantic span；semantic 高亮，scaffold 低亮。点击代码行：选命中范围中最窄的 semantic span，再回退到最近容器；无来源的标准脚手架只显示解释，不硬绑到不相关积木。

父子 span 可以重叠；子节点优先，选择父容器时才高亮其全部范围。运行错误使用该次运行的 source-map，不使用最新预览结果。

### 8.8 确定性与编译缓存

programHash 来自规范化 ProgramIR、compilerVersion、blockLibraryVersion 和影响代码的配置。排除 UI 坐标、缩放、当前选择、时间和随机 runId；保留块 ID 以稳定映射。相同输入必须逐字生成相同代码及 source-map。

参数编辑后 300ms 防抖请求编译；发送递增 requestId / revision，前端只接受最新请求对应结果，丢弃迟到结果。缓存命中只复用同一版本合同下的完整结果，不跨 compilerVersion 复用。

## 9. PyTorch 训练、尺寸验证和数值口径

### 9.1 MNIST 数据组织

MNIST 的 data 根目录下必须有 `MNIST/raw` 及相应图像和标签文件；root 指向 data，而不是 `MNIST/raw` 本身。torchvision 的 MNIST 接口将下载作为显式选项，因此这里固定 `download=False` 并在执行环境内验证可读取性。[T3]

```text
data/
└── MNIST/raw/
    ├── train-images-idx3-ubyte
    ├── train-labels-idx1-ubyte
    ├── t10k-images-idx3-ubyte
    └── t10k-labels-idx1-ubyte
```

主流程假设老师准备的是当前冻结 torchvision 版本可读取的格式。CIFAR10 / FashionMNIST 使用各自官方 Dataset 适配器做 `download=False` 的实际构造探测，不以“data 目录非空”当作通过。

训练数据只在目标环境中读，不通过本地 FastAPI 内存中转全部样本。预检最多抽取少量样本的 shape/dtype/label 摘要；不扫描整个数据集算散列，不上传完整样本到外部服务。

### 9.2 有限、静态的尺寸检查

本版本只检查已支持的顺序网络，不做一般神经网络形状推导引擎。由 Dataset 元数据提供输入 `[C,H,W]`；Conv2d 和 MaxPool2d 使用当前固定参数计算输出尺寸；ReLU/Dropout 保持尺寸；Flatten 将非 batch 维相乘；Linear 检查最后一维。

一般空间尺寸公式：

```text
out = floor((in + 2*padding - dilation*(kernel-1) - 1) / stride + 1)
```

MNIST 示例的验收轨迹：

```text
[N,1,28,28]
→ Conv(1,16,3,pad=1) → [N,16,28,28]
→ Pool(2)           → [N,16,14,14]
→ Conv(16,32,3,pad=1)→ [N,32,14,14]
→ Pool(2)           → [N,32,7,7]
→ Flatten           → [N,1568]
→ Linear(1568,128)   → [N,128]
→ Linear(128,10)     → [N,10]
```

该轨迹是依据层参数直接计算出的验收值。尺寸错时报到具体的 Conv/Linear 块，提供“上一层输出为 1568，当前填写为 1500”的说明，不静默改参数。遇到未来未知层，只能明确报告不支持，不猜测形状。

### 9.3 设备与可复现性

沿用原示例：CUDA 可用则 CUDA；否则可用 MPS；否则 CPU。只有运行所在 Python 环境的探测结果有效，不能用本机 GPU 信息决定远程 device。[R2]

若 CUDA/MPS 不可用，按规则使用 CPU 并显示原因；若选择后在实际执行中出现 OOM 或设备错误，正常失败，不能在中途无提示切 CPU 重新跑。记录 Python/torch/torchvision 版本、device、平台、seed、实际 workers、batchSize 和执行模式。

默认 seed=42，设置 Python random、torch 及 CUDA 的相关 seed，shuffle 使用明确的 torch.Generator；若用 numpy 才设置 numpy seed。说明固定 seed 不意味着跨硬件、跨版本逐位一致。不要把“可重复实验配置”宣传成绝对数值确定性。[T10]

### 9.4 训练与测试循环的精确定义

每轮开始 `model.train()`。每个 batch 将 x/y 移到 device，forward，计算 loss，`optimizer.zero_grad()`，`loss.backward()`，`optimizer.step()`。CrossEntropyLoss 输入为 `[N,10]` 未归一化 logits，目标为 `[N]` 整数类别；末层不添加 Softmax，避免重复归一化。[T6]

训练损失按样本数加权：

```python
total_loss += float(loss.item()) * int(x.size(0))
total_samples += int(x.size(0))
train_loss = total_loss / total_samples
```

最后一个小 batch 不能与其他 batch 等权平均。空 loader 必须预检失败或产生明确错误，不能除以零。非有限 loss 立即终止并报告，不输出 NaN JSON。

每轮训练结束后调用 `model.eval()`，在 `torch.no_grad()` 下遍历测试 loader，使用 `argmax(dim=1)`，计算 `correct / total`。完成测试后再发 `epoch_completed`，再执行 body 图表。下一轮恢复 `.train()`。测试与预测不反向传播。[T6][T11]

### 9.5 指标单位

| 字段 | 类型与范围 | 含义 / 显示 |
| --- | --- | --- |
| epoch | integer，1-based | 已完成的 epoch |
| train_loss | finite float，≥0 | 按样本数加权的训练平均损失 |
| test_accuracy | finite float，[0,1] | 测试集准确率，界面/图轴格式化为百分数 |
| train_samples | integer，>0 | 本轮实际训练样本数 |
| test_samples | integer，>0 | 本轮实际测试样本数 |
| elapsed_seconds | finite float，≥0 | 自运行开始的时间 |

历史数组采用 `epoch_history`、`train_loss_history`、`test_accuracy_history`；test_accuracy 始终存 0～1，不一处存百分数、一处存小数。界面使用格式化器乘 100；CSV 中保留原始小数。输出日志可显示 `Acc: 97.30%`，日志不是指标解析源。

原示例每轮查看测试集。本版本忠实保留该教学行为，但 Tutorial 必须说明：反复查看测试表现不等于严格独立的最终泛化评估；后续需要分离验证集。此版本不增加验证集划分、最佳模型选择或 early stopping。

### 9.6 模型权重与预测

正常训练结束后保存最终 `state_dict` 到本次运行的 `outputs/model.pth`，附属 run 元数据记录模型 ProgramIR、数据预处理、类名和依赖版本。文件使用临时名写完后原子替换。不要默认 pickle 整个模型对象，也不在本版本加载任意来源的权重执行推理。[T12]

预测选测试集固定前若干样本，最多 10 个，数量不足时按实际数量显示。先 `.eval()` 和 `no_grad()`；取回 CPU 后可视化；Normalize 后的张量显示时用对应 mean/std 反归一化并 clamp 到可显示范围。不要把经过归一化的值直接当 0～1 灰度，也不要为了画样本多跑一次完整测试集。

在 body 使用预测图时，每轮测试后仅对固定小样本做预测；after 的预测图可以复用最终结果。明确来源是当前 epoch / 最终模型。

## 10. 图表配置、渲染与产物关联

### 10.1 图表数据合同

折线图和散点图只读取已记录的 epoch 历史，不解析终端文字。默认将损失与准确率放在两个 panel 中，分别标注单位；学生主动将两者放在同一 panel 时允许，但显示“不同量纲不宜直接比较”的提示，不能不标单位地让它们看似同一尺度。

图像网格用一个 panel 内部的 rows/cols 管理样本格子。因此外层 layout=[1,1] 也能呈现 1×5 的训练样本，不必为了复现原示例额外增加一个 1×5 外层版式。

每张图的解析结果至少包含 figureBlockId、phase、epoch（可空）、layout、size、panels；每个 panel 包含 panelBlockId、chartType、数据源集合、样式。每个 source 保存自己的 blockId，以便选择配置时解释来源。

### 10.2 执行和保存

Runner 为训练子进程设置 `MPLBACKEND=Agg`；生成代码只导入所需 Matplotlib 模块。每次渲染创建独立 figure，显式使用 Axes，渲染完成执行 `fig.savefig(...)`，最后在 finally 中 `plt.close(fig)`。不让全局 pyplot 状态串到另一张图，不累计不关闭的 figure。[T5]

固定尺寸映射写入 manifest 或共享默认配置，例如小=(6,4)、中=(10,6)、大=(14,8)，单位英寸；PNG 的 DPI 固定并记录。预测图使用文本标明正确/错误，不能只依赖红绿颜色传递信息。

默认文件布局：

```text
outputs/figures/<blockKey>/before.png
outputs/figures/<blockKey>/epoch-0001.png
outputs/figures/<blockKey>/epoch-0002.png
outputs/figures/<blockKey>/after.png
```

blockKey 由 blockId 的 SHA-256 截取并做冲突检测得到；**不能把原始 Blockly ID 直接拼成文件名**，因为 ID 可能含路径不安全字符。

无 `viz.savefig` 也自动保存预览图。存在 savefig 时，将其相对路径作为逻辑名称，实际保存名加入 blockKey 与 phase/epoch，例如输入 `./outputs/loss.png`，界面预览实际路径 `outputs/loss__<blockKey>__epoch-0001.png`。具体规则统一放在 ArtifactPathResolver，前后端显示一致，不出现看起来写 A 实际写 B 而不说明的行为。

写入临时文件时显式指定 `format="png"`，完成、关闭文件后原子改名，再上报 artifact 事件。只有完整文件才可预览或同步。每轮保留一张历史图；默认显示最新图，可按 epoch 切换。

### 10.3 ArtifactRecord

```ts
export interface ArtifactRecord {
  artifactId: string;
  runId: string;
  kind: "figure" | "model" | "log" | "metrics";
  relativePath: string;              // 相对本次运行目录
  mimeType: string;
  sizeBytes: number;
  sha256: string;
  producerBlockId: string;
  contributorBlockIds: string[];

```

figure 的 producer 为 figureBlockId，panel/source/style/savefig 为 contributors；model 和训练日志的 producer 为 train.loop。没有精确来源的第三方日志只能关联到运行/训练根，不能声称精确到某个 Conv2d。

点击文件卡片定位 producer；“查看配置”可选择 contributors。定位历史产物时按运行快照处理。远程产物的事件到达不等于文件已下载，UI 必须区分“远端已生成”和“本地可打开”。

## 11. 运行协议、日志和事件恢复

### 11.1 不从普通 print 中提取指标

`easyai_runtime.py` 向 stdout 输出以 `@@EASYAI_EVENT@@` 开头的单行 JSON；其他 stdout / stderr 是普通日志。所有结构化事件限制大小并 flush。正常终端面板不显示协议前缀行。

子进程事件的最小负载：type、blockId（可空）、payload。runId、顺序号、时间和来源由 supervisor 校验并补齐，不能盲信输出内容。事件类型包括 `runtime_started`、`device_selected`、`progress`、`epoch_completed`、`artifact_created`、`runtime_error`、`pipeline_cancelled`、`pipeline_completed`、`process_exited`。

只有训练进程的主线程发送结构化事件；DataLoader worker 不创建 RunContext、不写结构化指标。stdout 的普通日志读取与 stderr 并发进行，避免一个管道填满导致死锁。[T9]

### 11.2 两层事件编号与唯一写入者

为解决远程断线、本地预检事件和恢复的顺序问题，使用两层日志，而不是让多进程同时写同一个 events.jsonl：

- **执行日志**：执行侧 supervisor 是 `logs/runtime-events.jsonl` 的唯一写入者，分配递增 sourceSeq。SSH 断开后仍在远端继续落盘。
- **应用日志**：本地 RunService 是 `logs/events.jsonl` 的唯一写入者，给控制事件和拉回的执行事件分配递增 seq。前端 SSE 只消费它。

执行事件按 `(runId, sourceSeq)` 去重。重启时从完整应用日志重建已接收的 sourceSeq 和最后 seq；cursor 文件只是加速缓存，不是比日志更可靠的第二份事实。若最后一行写入不完整，只处理之前完整行并记录恢复情况，不重新执行训练。

```json
{
  "protocolVersion": 1,
  "runId": "83c0e86a-cf6d-4c56-95a5-3c8bd1a5e42b",
  "seq": 18,
  "source": "runtime",
  "sourceSeq": 12,
  "timestamp": "2026-10-18T12:30:00Z",
  "type": "epoch_completed",
  "blockId": "train-loop-1",
  "payload": {
    "epoch": 1,
    "train_loss": 0.3124,
    "test_accuracy": 0.9412,
    "train_samples": 60000,
    "test_samples": 10000,
    "elapsed_seconds": 32.8
  }
}
```

上面的数值只用于事件格式示例，不是本项目已取得的训练结果。

### 11.3 日志、CSV 和内存控制

普通 stdout 原文落 `train.log`，stderr 落 `stderr.log`；保留两者来源，不承诺两个 OS 管道间绝对精确的时间顺序。后台持续排空管道，界面暂停滚动不得暂停读取。

metrics/epochs.csv 从规范事件生成，字段固定为第 9.5 节定义。重复事件不得重复追加同一 epoch；恢复时可以从 events.jsonl 重建 CSV。应用日志是本地指标视图的事实来源，CSV 是导出格式，不与事件相互覆盖。执行侧 supervisor 只需保证原始执行事件持久化；远端不必另写第二份 CSV。重连时先补事件，再重建本地 CSV。

正在增长的 train.log、stderr.log 和 CSV 通过专门的日志/指标读取流程展示，不作为带固定 SHA-256 的不可变文件反复下载。终态确认并补齐内容后再登记它们的最终 size/hash；PNG 和权重在原子落盘后即可登记为不可变 ArtifactRecord。

前端日志采用虚拟列表，只保留有限窗口，历史可分页读取。progress 最多每秒更新一次；每个 epoch_completed 和 artifact/error/terminal 事件不可丢。上传下载按字节进度展示；训练没有可靠总耗时预估时只展示已完成 batch / epoch，不伪造剩余时间。

### 11.4 SSE 合同

`GET /api/v1/runs/{runId}/events?after=<seq>` 返回 SSE：`id` 为 seq，`event` 为 type，`data` 为规范 Event JSON。先补发 after 之后的已落盘事件，再发送新事件；约 15 秒心跳一次；重连从最后已处理的 seq 继续，客户端按 seq 去重。

SSE 由 Electron Main 连接并转发为类型化 IPC 事件，renderer 看不到 token。取消订阅必须移除 IPC listener 和 SSE 连接；切换标签不能重复订阅制造双倍指标。

本版本不再同时实现 WebSocket 作为另一条实时通道。网络变化时使用指数退避重新连接，终态确认且事件追平后可以关闭实时连接。

## 12. Runner、本地执行与取消

### 12.1 统一 Runner 合同

```python
from pathlib import Path
from typing import Protocol


class Runner(Protocol):
    async def preflight(self, config: "RunConfig") -> "PreflightReport": ...
    async def stage(self, bundle: Path, config: "RunConfig") -> "RunHandle": ...
    async def start(self, handle: "RunHandle") -> "StartResult": ...
    async def request_cancel(self, handle: "RunHandle") -> "CancelResult": ...
    async def read_events(self, handle: "RunHandle", offset: int) -> "EventChunk": ...
    async def inspect(self, handle: "RunHandle") -> "ExecutionStatus": ...
    async def fetch_artifact(self, handle: "RunHandle", artifact: "ArtifactRecord") -> Path: ...
```

RunHandle 必须包含 runId、目标 ID、代码 hash、实际执行目录、启动身份和事件 cursor；不可把 SSH 密码作为可序列化字段。

LocalRunner 与 SSHRunner 共享 RunService、编译结果、Runtime bundle、事件解析、错误映射和产物 schema。区别集中在“如何放文件、起进程、读取文件、发送取消请求”。

### 12.2 状态机

```text
CREATED → PRECHECKING → STAGING → STARTING → RUNNING → SUCCEEDED
                  └──────────────────────────────→ FAILED
任一尚未结束的阶段 → CANCELLING → CANCELLED
证明进程已消失且没有可靠终态记录 → INTERRUPTED
```

connectionState 独立取 `connected / disconnected / reconnecting`；syncState 独立取 `pending / syncing / complete / error`。SSH 断线不是 FAILED；训练结束但图像未同步不是“训练还在运行”。没有证据确认执行结果时保留最后已知状态并显示未知，不能编造退出码。

SUCCEEDED 必须满足：训练子进程退出码 0、收到 pipeline_completed、要求的最终权重和已配置图像在执行侧完整生成。后续本地同步失败保留训练成功状态，但标记结果未完整获取并支持重试。

同一个项目同时只允许一个活动运行。本地客户端同时只启动一个训练任务，降低课堂原型的资源竞争；其他项目仍可编辑。环境安装任务与使用同一环境的训练互斥。重复点击运行以 Idempotency-Key 返回同一个 runId，不能启动两个进程。

### 12.3 运行前检查

检查顺序：工程 runnable → 运行位置连通 → Python/包可导入 → 数据可读取 → 输出目录可写 → 同项目无活动任务 → 运行配置和代码 hash 一致。尽量在创建 GPU 大对象前给出可理解的错误。

RunConfig 使用后端解析出的绝对 dataRoot、runRoot、environmentPrefix、pythonExecutable；生成代码通过参数/子进程环境接收，不依赖 Electron 的当前工作目录。环境变量只设置在该子进程，不修改用户全局 shell 配置。

预检只说明当时的条件满足，不保证后续永远不出错；训练启动后仍捕获缺文件、权限变化和设备错误。

### 12.3.1 RunConfig 与代码导出入口

RunConfig 必须有独立 schema，最低字段如下。全部路径由后端解析；上传给执行侧的版本不包含本地凭据或整个连接配置。

```ts
export interface RunConfig {
  configVersion: 1;
  runId: string;
  projectId: string;
  projectRevision: number;
  programHash: string;
  codeHash: string;                  // train.py UTF-8 内容的 SHA-256
  bundleHash: string;                // 排序后的代码/辅助文件路径和 hash 的摘要
  targetId: string;
  runner: "local" | "ssh";
  dataRoot: string;                  // 执行目标上的绝对路径
  runRoot: string;                   // 执行目标上的绝对路径
  pythonExecutable: string;
  environmentPrefix?: string;
  executionMode: "full" | "quick";
  seed: number;
  numWorkers: number;
  pinMemoryPolicy: "cuda_only";
  quickLimits?: { epochs: 1; trainSamples: 1024; testSamples: 256 };
}
```

bundleHash 不包含它自己、runId、执行状态、日志和动态运行配置；以相对文件路径、固定排序和文件内容 hash 计算。RunConfig 的动态字段另存配置摘要，不能只凭 codeHash 宣称两次运行的数据位置和执行模式完全相同。quick 模式覆盖本次实际 epoch/样本上限，但不改原积木中的正式参数；实际值进入运行元数据和事件。

`RunContext.from_cli()` 的公共参数固定为 `--data-root`、`--output-dir`、`--seed`，由代码导出说明展示；应用内部另支持 `--config <run-config.json>`。两种入口互斥，配置错误直接解释并退出，不猜测当前目录。独立导出运行示例：

```bash
python code/train.py --data-root "/absolute/path/to/data" --output-dir "/absolute/path/to/new-output" --seed 42
```

独立运行没有应用事件消费者时，辅助模块仍输出可读进度，并由同进程的文件 sink 保存事件、CSV 和产物清单；该模式不启动另一份 RunService。应用模式由 supervisor / RunService 按第 11 节分工，不能同时启用独立模式的第二个 journal 写入者。新输出目录不得覆盖已有运行；完整导出还需提供 requirements/环境说明和 source-map。

### 12.4 Supervisor 的最小实现

supervisor.py 是每次运行带上的标准库脚本，不是远程服务。它负责启动 `entry.py`，entry.py 再用 `runpy.run_path(..., run_name="__main__")` 执行 train.py。entry.py 把异常结构化后以非零码退出。

Supervisor 同时读取 stdout 和 stderr，放入线程安全队列；单一写入循环生成 runtime-events.jsonl、更新执行状态。状态文件采用原子替换，包含 pid、开始时间、runId、启动随机标识和最后活动时间；不只记录一个裸 PID。

子进程通过当前环境的 `sys.executable -u entry.py` 启动，参数列表传给 subprocess，`shell=False`；cwd 指向本次 run 目录；代码路径和 dataRoot 为绝对路径。不要在 FastAPI 内 import 并执行 train.py。[T9]

进程生命周期与文件写入错误必须可观测。日志目录写满时停止训练并尽可能输出 I/O 失败记录；不能只继续计算但不保存任何结果。

### 12.5 取消与进程清理

先写入带本次启动标识的 `cancel.request.json`。RunContext 在训练/测试每个 batch 边界及每个图表阶段检查取消，抛出专用 Cancelled 异常；entry.py 产生取消事件并退出。

Supervisor 也持续检查取消文件。若 5 秒内未退出，进行软终止；再等待 3 秒仍未退出则强制终止。这些是代码的取消策略，不是对所有硬件故障的绝对完成保证。

POSIX：训练子进程使用独立 session/process group，取消升级时终止其进程组，包含 DataLoader worker；不能使用 `pkill python`、`killall` 或靠进程名杀其他学生作业。[T9]

Windows：本版本实际训练的 num_workers 固定 0，Runtime 不启动其他外部子任务，Supervisor 直接持有训练子进程句柄。调用 terminate/kill 只针对本次持有的进程；不能声称 Windows 的 terminate 会自动清理任意孙进程。将来开放多 worker/外部子任务前必须增加 Windows Job Object 等进程树管理并补测试。[T9]

取消期间保留日志、已完成指标和图像，不生成假“最终完整权重”。任务已经成功退出后才收到取消请求，应返回原终态，不能把成功改为取消。

### 12.6 应用关闭与恢复

有本地运行时退出需询问是否停止任务并退出，默认不留下本地训练孤儿进程。有远端运行时允许明确选择“继续在服务器运行并退出”，说明重新打开后恢复查看；默认关闭窗口不自动删除远端目录。

正常关闭必须等待本地取消处理并清理 sidecar。非正常崩溃后，下次启动按身份检查进程和执行状态，重建事件 cursor；不会自动重跑旧任务。保存的 PID 不足以证明进程身份，身份无法验证时只能提示人工检查，不能误杀复用 PID 的进程。

## 13. SSH、远端路径与断线处理

### 13.1 连接配置

字段包括 host、port（默认 22）、username、认证方式（密码或私钥）、私钥选择、可选口令、conda 可执行位置、远端运行根目录、数据根目录。普通模式展示最少字段，高级模式展开路径和连接超时。

只支持单跳 SSH 到 Linux；不实现跳板机/ProxyJump、Windows SSH 服务器、调度系统作业提交、端口转发和远程桌面。若学校服务器要求 Slurm 等调度器，不绕开管理员规定直接运行，报告该执行方式未支持。

密码和口令只存会话内存。v0.0.0 不提供“记住密码”；私钥不复制进工程。连接概要只存 host/port/username、私钥文件的本机引用及非敏感设置。

### 13.2 主机密钥校验

已知主机从应用维护的 known_hosts 与用户确认的信任记录加载；默认拒绝未知/变化密钥，不调用 AutoAddPolicy 静默信任。首次连接先完成握手获取公钥指纹，展示 SHA-256 指纹，要求用户与老师提供的信息核对后显式确认；密钥变化时阻断并解释，不自动覆盖。[T7]

允许在认证之前完成主机密钥确认。凭据不写入调试日志；连接失败只保留脱敏摘要和错误类型。连接/认证/命令探测分别设置超时，所有 Paramiko 阻塞操作通过线程池或专用工作线程执行，不能阻塞 FastAPI event loop。

### 13.3 远端目录和数据绑定

默认应用写入目录为该用户 home 下的 `.easyai/projects/<projectId>/runs/<runId>/`；实际 home 在远端解析，不能把本机 `~` 展开结果当作远端 home。

数据提供两种明确模式：

**使用老师准备的服务器数据**：设置远端绝对 dataRoot，预检只读，不同步、不移动、不写入该目录。本地项目的 data/ 可以为空。

**上传本地 data**：用户点“上传本地数据”后，先显示源目录、目标目录、文件数量与总字节数；拒绝 symlink；目标仅限应用管理的数据目录；逐文件 SFTP 上传到 `.part`，校验后改名。大数据集不在点击“运行”时隐式上传。中断可以重新按 manifest 检查后重传缺失文件，不要求实现任意字节级断点续传。

两种模式均将实际解析后的 dataRoot 存入本次运行元数据；共享工程默认不包含机器特有的绝对路径。执行 Bundle 只含代码、快照和配置，不含整个项目仓库、SSH 私钥或无关大文件。

### 13.4 远端启动协议

1. 通过 SFTP 建立该 runId 专有暂存目录，逐文件上传 `.part` 后改名；记录文件 hash。
2. 上传固定版本的 supervisor、entry、runtime helper、train.py、source-map 与 run-config。确认所有必要文件齐全和 codeHash 匹配。
3. 使用选定 conda 环境或明确 Python 执行 `supervisor.py --start --run-dir <abs>`。所有路径独立安全引用；运行参数写 JSON，避免复杂配置塞进 shell。
4. `--start` 在目标环境中用 `sys.executable` 派生 `--serve` 实例，继承已激活环境；将 stdin 断开、stdout/stderr 重定向至本次运行日志；POSIX 使用独立 session。远端不是依赖 SSH channel 活着才继续执行。
5. 通过独占创建启动锁和 run 启动标识防止重复启动；重复 `--start` 返回已有身份。确认状态文件与 heartbeat 后，应用才能标记已启动。
6. 后续用 SFTP 读取 runtime-events.jsonl 和执行状态，不长期占用 `tail -f` 命令，也不在远端开 HTTP 监听端口。

Paramiko 的 exec_command 接受命令字符串，远端通常经 shell 解释；因此本地 subprocess 的 `shell=False` 不能被误认为自动解决 SSH 注入。远端仅生成白名单命令和经过 POSIX `shlex.quote` 的独立参数；禁止把用户字段直接拼入命令。[T7]

### 13.5 增量读取与重连

以字节 offset 读取远端日志；UTF-8 采用增量解码，跨读取边界的半个字符/半行缓存到下一次，不能每次独立 decode 后丢失尾部。正常轮询间隔以约 500ms～1s 为初始配置，批量读取完整行。

网络中断时显示“暂时无法读取服务器状态，任务可能仍在运行”。保留 runId、远端目录、host 指纹、sourceSeq 和 offset，暂停同步但不标记失败。重连先检查主机身份和 run 身份，再补事件和产物，不重新执行 start。

取消请求在断线期间只能标记“待发送”；不得显示“已停止”。恢复连接后核实任务是否已结束：结束则保留终态，仍运行才发送取消请求。取消返回成功的标准是执行侧已确认终止，不是本地按钮变灰。

### 13.6 产物同步

只下载经过 schema 和路径校验的 artifact manifest 中的文件。远端路径必须在该 runRoot 内，所有路径组件拒绝越界和符号链接；不能使用字符串前缀比较替代规范化路径检查。

下载到本地 `.part`，验证 size/hash，原子替换后将 syncState 标记 ready。同一 runId 内凭 hash 去重；下载失败可重试，不能损坏已同步文件。只预览受支持的 PNG 和文本，不执行远端返回的 HTML / JS / 可执行文件。

完成训练后补齐执行事件和最终日志，从本地规范事件生成 metrics/epochs.csv，并下载、校验最终权重。不要尝试读取一个执行侧从未承诺生成的远端 CSV。远端目录默认保留；清理不属于自动启动/同步流程。

## 14. conda 与包组管理

### 14.1 环境探测优先于安装

先允许学生选择课程现成 conda 环境。探测 conda 可执行文件、`conda info --json` 和 `conda env list --json`；在非交互 SSH 会话中，conda 不一定在 PATH，需要有限的标准位置探测或用户提供绝对路径。

执行采用 `conda run -p <prefix> --no-capture-output ...`，不依赖 `conda activate` 改变另一个独立 SSH 命令的 shell 状态。conda run 的环境选择、工作目录和输出控制有对应官方接口。[T8]

Windows 不能把任意 `.bat` 路径直接当安全可执行文件。CondaCommand 优先使用经过验证的 conda.exe；或使用 base 环境的 `python.exe -m conda` 作为 argv 前缀。二者都用参数列表、shell=False；不增加接受自由文本的 cmd.exe 拼接兜底。

未安装 conda 时仍允许选择明确的 Python 解释器并通过依赖探测；自动创建训练环境仅在支持的 conda 路径下启用。v0.0.0 不自动安装 conda、GPU 驱动或系统 CUDA Toolkit。

### 14.2 探测必须用选中的真实环境

运行固定 probe.py，输出结构化 JSON：Python 路径/版本、sys.prefix、torch/torchvision/matplotlib 版本、实际 import 结果、CUDA/MPS 可用性、一次小张量/卷积执行、指定 Dataset 的离线读取检查。

包“已安装”不能只依据 pip list，因为 torchvision 与 torch 二进制不匹配仍可能导入失败。探测在独立子进程中进行，超时可终止；不把 torch 加载到应用 sidecar 中。EnvironmentProbeReport 保留各项检查和修复建议，失败时不要只给红叉。

### 14.3 包组与功能状态

保留原文包组目录，去重按 Python distribution 名称进行：[R2]

```text
ml : numpy, scipy, pandas, matplotlib, scikit-learn
dl : torch, torchvision, pytorch-lightning
cv : pillow, opencv-python, scikit-image
nlp: nltk, spacy, sentencepiece, transformers, gensim, hanlp
```

MNIST 最小依赖集合由 profile 单独定义，至少包含经过验证的一组 torch、torchvision、matplotlib 及其依赖；不要求学生为此安装全部 ml/dl/cv/nlp。

包卡片展示用途、是否已安装、已装版本、所选 profile 的目标版本、直接依赖说明和可用操作。包组全选与单包勾选走同一安装计划生成器。下载体积无法从已获取的元数据可靠确定时显示“待解析/未知”，不能编造固定包大小；已获取真实 wheel 元数据时才展示估计，并区分下载量与安装占用。

distribution 名与 import 名通过显式映射维护，例如 scikit-learn→sklearn、pillow→PIL、opencv-python→cv2。不要用把连字符换下划线的方法猜测 import 名。

### 14.4 安装边界

教师现有环境默认为只读。第一次需要新增包时，推荐新建应用拥有的环境；禁止默认升级或降级共享环境中的 torch。自动写入只允许带 ownedByEasyAI 标记且路径在本应用环境根目录内的环境。

训练 profiles 至少包括 `teacher-existing`（只检测，不改动）和 `easyai-cpu`（经过验证的受控安装方案）。GPU 环境默认使用教师已配置环境；没有经过目标驱动/平台验证的 CUDA profile 时，不允许猜一个 wheel 源自动安装。

安装只接受目录中白名单 packageId、受信任索引配置和 profile constraints，不接受任意 shell 字符串或任意 requirements URL。安装前显示目标环境、计划新增/变更的包及是否联网，由用户确认。训练按钮绝不自动执行 pip。

### 14.5 安装任务流程

先只读探测目标环境或受控的新环境目录 → 解析用户选择、依赖和 profile 约束 → 生成带基线环境指纹的 InstallPlan → 显示计划并取得用户确认 → 创建 InstallJob → 获取环境互斥锁 → 重验环境指纹和 planHash → 记录安装前包版本 → 执行 conda 创建/环境内 `python -m pip install` → 持续记录日志 → 再次真实 import 与张量探测 → 保存安装报告 → 释放锁。

计划生成阶段不得安装软件。若确认后环境已变化，返回计划过期，重新解析和确认，不沿用陈旧计划继续修改。创建新环境时，计划可以使用 newEnvironmentSpec 而不要求一个尚不存在的 ownedEnvironmentId；名称经过校验，实际 prefix 由后端在应用受控环境根目录内分配。

默认不加无边界 `--upgrade`；若可选包与现有 torch/torchvision 约束冲突，明确失败并建议单独环境，不自动解决为破坏核心训练环境的版本组合。离线且缺包时显示缺失项，允许换用已配置环境，不无限重试联网。

安装事务不能承诺完整回滚。失败时记录已发生变更；应用新建的环境可在单独确认后重建，教师环境不自动清理。取消安装停止本次安装进程并将环境标记“需要重新检查”，而不是立即宣告环境健康。

## 15. 后端 API 与前后端合同

### 15.1 合同生成原则

Pydantic 模型是 API/工程/事件 schema 的权威源码；构建时导出 JSON Schema / OpenAPI 到 `packages/contracts/schema`，再生成 TS 类型与客户端。生成文件不可手工维护成另一套 schema，CI 运行同步检查并要求无 diff。

积木 manifest 是另一类声明源：描述积木种类与字段，而不是重复定义整个 API。后端按 manifest 校验积木语义，前端用同一 manifest 建立 UI。两者的职责不要混淆。

前端使用强类型客户端和固定 preload 方法。所有 HTTP 路径前缀为 `/api/v1`，所有请求带会话鉴权；敏感请求日志必须脱敏。

### 15.3 API 错误与工程诊断

HTTP 401 表示会话鉴权失败；403 表示路径/操作不授权；404 表示已登记资源不存在；409 表示活动任务冲突；412 表示 revision / programHash / install-plan 已过期；422 表示请求结构错误。服务器异常为 500 并生成 requestId，不能把全部异常都返回 200。

合法但未完成的积木工程编译返回 200、`runnable=false` 和 diagnostics；已接受的后台运行失败体现在 Run 状态和事件中，不试图把已返回的 202 改成 HTTP 500。

统一错误体：

```json
{
  "error": {
    "code": "PROJECT_REVISION_CONFLICT",
    "message": "项目已发生变化，请保存当前修改后重新运行。",
    "requestId": "request-001",
    "details": {"expectedRevision": 3, "actualRevision": 4}
  }
}
```

UI 若刚完成保存，必须使用保存返回的新 revision 和针对该版本的 programHash。不能拿保存前的预览 hash 直接启动，造成看起来有“随机过期错误”。

## 16. 工作区、错误处理与 Tutorial

### 16.1 三个 workspace 的生命周期

三个标签页各持有一个 workspace 实例，封装在 WorkspaceManager 中。React 重渲染不重新 inject；卸载时 dispose、移除监听器和 resize observer。切换标签后执行适当 resize，避免隐藏容器尺寸导致坐标错位。

Blockly 变化事件区分语义事件与纯 UI 事件。只对语义变化更新注册索引、编译和 programHash；选中事件只更新说明/代码高亮。批量导入/模板加载时暂停自动保存与编译，完成后统一触发一次。

不能把 Blockly workspace、block 实例、Monaco editor 实例序列化进 React store。Store 只保存可序列化状态和少量稳定引用 ID，真实实例放在受控管理器/ref 中。

### 16.2 错误处理分三层

**编辑期**：字段格式、重名、引用失效和连接错误。显示在具体字段/积木，并收敛到问题列表。

**运行前**：环境、数据、权限、设备探测和静态尺寸不匹配。错误导航到环境/数据配置，不伪装成变量错误。

**运行时**：保留完整技术栈，同时将可识别错误映射为中文解释。原文要求的 NameError 必须完成结构化处理。[R2]

### 16.3 NameError 的实现流程

entry.py 捕获异常对象，提取类型、message、`NameError.name`（可用时）和 traceback frame 的 filename/lineno/function。以 runtime_error 事件上报，不仅发送已经格式化成字符串的 traceback。

后端先核对生成代码 hash，再从最内层属于本次 `train.py` 的 frame 找行号，以 SourceMap 的最窄 semantic span 定位块；只有库内部 frame 且没有可映射位置时，回退到最近的生成代码调用位置或训练根，明确定位精度。

展示示例：“生成代码使用了 `train_data`，但未找到它的定义。请检查数据对象是否被删除、取消注册或改成了其他引用。”提供“定位积木”“检查注册对象”“查看原始错误”。若工程引用检查全部通过仍发生 NameError，应标记可能为生成器缺陷并支持导出脱敏问题报告，不把编译器 bug 一概归咎学生。

建议来自规则和当前符号表，不调用 LLM 猜修复。可以提示同类型名称相近的候选，但不能自动替换引用。由于正常项目应在编译期拦截失效引用，运行时 NameError 测试使用测试专用错误代码 fixture 注入；不要为制造演示错误增加任意 Python 执行功能。

### 16.4 最小错误码目录

| 错误码 | 中文主提示 | 导航位置 |
| --- | --- | --- |
| NAME_INVALID / NAME_DUPLICATED | 名称不符合规则 / 已有同名对象 | 定义积木 NAME |
| REF_NOT_FOUND / REF_NOT_REGISTERED | 选择的对象不存在 / 尚未供本项目引用 | 引用字段 |

### 16.5 Tutorial 最小交付

内置本地 Markdown 教程至少覆盖：Dataset 与 DataLoader 的区别、batch 与 epoch、卷积/池化/Flatten、loss 与 accuracy、训练与测试模式、设备与运行环境、如何阅读错误和输出。

每篇关联 relevantBlockTypes 和操作入口，例如“定位本例的 DataLoader”“显示对应代码”“打开 MNIST 示例副本”。教程操作不得无提示覆盖未保存工程；不创建独立的第四个计算工作区。

必须实现一个真实的轻量交互：用固定 5×5 数值矩阵和可编辑 3×3 kernel 显示窗口位置、逐项乘积、求和与输出网格；移动窗口时即时重新计算。它是 React/Canvas/SVG 的本地数值演示，不是完整训练计算引擎。单元测试用全 1 输入与全 1 kernel，合法 3×3 窗口和为 9；改变一个 kernel 项时结果按算术变化。

不做长篇课程平台、测验系统、教师管理后台或所有神经网络算子动画。Tutorial 的解释必须与本版本实际训练语义一致，尤其是测试准确率、设备回退、固定 seed 和代码只读。

## 17. 安全、可靠性与资源约束

### 17.1 不可妥协的边界

本软件不是不可信 Python 的安全沙箱。仅支持应用内置积木生成的代码，不提供执行任意脚本入口。项目文件仍视为不可信数据，要校验，不能因为是本地软件就直接读取任意路径或执行项目指定的模板。

所有外部文本按文本展示；日志/教程中的未经信任 HTML 不直接渲染。图像仅从已登记 artifact 获取。外链通过明确的 http/https 白名单处理，不调用带任意协议的 shell.openExternal。[T1]

API 参数不能传给 `eval`；包安装不能接受任意命令；远端取消不能杀进程名；路径检查包含 Windows drive/UNC、POSIX 绝对路径、`..`、反斜杠变体与 symlink。对不存在的输出路径，要校验所有已存在父目录的实际位置。

### 17.2 初始资源限制

配置集中在 Limits 中：工程 JSON 上限 5 MiB、积木总数 500、嵌套深度 64、单行结构化事件 64 KiB、单个自动拉回产物默认 100 MiB；超过上限给出具体说明，不静默截断工程或模型。数字字段还应有防止异常超大分配的保守上限，写在 manifest 中并有测试。

日志读取分块、界面分页；不对 data/ 无界递归、不在 UI 线程读取整个大文件。所有 API/SSH 操作有 timeout 与可取消路径。后台磁盘任务不会冻结窗口拖拽。

本节数值是首版可调整策略，不是经过性能测试的最优值。需要在 M8 中记录测试机器、工程规模、日志规模和实际结果，再决定调整。

### 17.3 性能验收目标

以 200 个积木的参考工程为目标：标签切换和选中响应不明显卡顿；一次参数修改后的代码预览目标在 1 秒内更新；日志和 epoch 指标在目标环境产生后，健康连接下目标 2 秒内可见。把这些作为待测目标，不宣称当前已经达到。

保存时不阻塞长时间训练；SSH 断线时工作区仍可编辑；持续日志不能让前端内存随运行时间无限增长。对失败、超时、取消和恢复的检查优先于增加装饰性界面效果。

## 19. 自动化测试与验收矩阵

### 19.1 四层数据策略

纯编译与 schema 测试不安装 torch、不联网。Runtime 协议测试使用小型标准库 fixture 进程，产生可控制的 stdout、stderr、错误和退出码。

真实训练集成测试使用测试生成的合法 IDX 图像/标签数据或预置的小型合规 fixture，在真实 torch/torchvision 环境执行；目的仅是验证代码与运行链，不声称衡量 MNIST 准确率。普通 PR CI 不依赖外部数据下载站点。

真正 MNIST 数据只用于已准备的集成环境/手工课堂验收。数据准备脚本必须是显式执行的教师/开发命令，说明下载来源和目录，不混入普通训练启动。

GPU、MPS 和真实校园 SSH 测试需要对应硬件/权限。缺资源时报告未运行；发布声称支持的平台和主 SSH 路径必须补齐实际记录。

### 19.3 真实 MNIST 验收标准

本地 CPU 小样本和 SSH 目标正式示例都应记录工程 hash、依赖版本、设备、运行命令、epoch 数、实际损失与测试准确率、输出数量和测试时间。正式示例产生 10 条完整 epoch 记录、最终权重和配置对应的图像；数值有限、准确率位于 [0,1]、样本统计与实际运行一致。

不在未做基准测试前硬写“10 轮必须达到 99%”等保证。学习效果由真实运行基线审查：检查是否明显偏离该模型应有的行为，发生异常时检查数据预处理、梯度更新、eval 和标签，不以调低验收阈值掩盖逻辑错误。

CI 的 synthetic fixture 不承担准确率阈值；它可以断言参数确实发生更新、测试不更新权重、指标计算精确。前后端展示值要能与保存的事件/CSV 独立核对。

### 19.4 CI 与报告要求

每个 PR 跑静态检查、合同同步、纯编译/协议测试；独立作业在冻结的 CPU 训练环境运行真实集成测试；桌面 smoke 在已选目标 OS 运行；SSH 测试使用临时隔离目标或明确指定的测试服务器。

发布报告列出 PASS / FAIL / NOT RUN，而不是只有绿色总数。最后一个状态不是 PASS。对安装包启动、真实 SSH、取消清理和源码映射的关键失败，不得以“其他单元测试通过”放行。

## 20. 后续扩展必须保留的接口

### 20.1 新增一个层不应该修改训练引擎

例如未来增加 `model.avgpool2d`，只应需要：新增 manifest、字段/placement/shape 规则、可信 model emitter、教程说明和测试；不得修改 LocalRunner、SSHRunner、事件协议或项目主格式。

如果新增一层需要在 React 页面、训练模板和 SSH 代码里同时加 `if layer == ...`，说明边界已经被破坏，应先修复分层。当前无需真的实现 avgpool2d，这只是扩展验收准则。

### 20.2 移除/修改积木不应破坏旧工程

块 ID 与已有字段语义不得无版本变更地复用。字段新增有默认值；不兼容变更走 migration；删除块先 deprecated，再提供替代映射或只读提示；未知块原文保留。

编译器版本、运行协议版本和 blockLibraryVersion 分开演进。不能为了增加一个积木迫使用户迁移全部日志，也不能把 UI 字段值变更伪装成同一个版本。

### 20.3 未来增加多模型、更多数据和远端执行方式

多模型通过放宽 RegistryPolicy 数量约束和扩展 TrainingSpec 处理，不修改 ID 引用原理。CSV / 自定义 Dataset 增加 DatasetAdapter 与任务元数据，不把 MNIST 专用 `.data` 用法散落在可视化核心。

新的 Runner（例如调度系统）实现第 12 节合同，并声明支持的能力；不让模型编译器理解服务器命令。未来一般 shape 推导、验证集、断点恢复和用户自定义 Python 都是独立版本能力，不能以“接口已预留”宣称本版本已支持。

本版本不实现动态插件安装或热加载。扩展通过受信任源码和版本发布进行，避免把可扩展性变成任意代码加载入口。
