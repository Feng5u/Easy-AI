# 设计文档

## 一、产品定位

一款面向**无编程基础、专业无编程要求本科生**的 AI 通识教育工具。核心形态是类 Scratch 的积木拖拽编程环境，后台自动生成完整可运行的 PyTorch 代码。目标不是培养程序员，而是让学生在通识课程中**走通从数据读入到训练结束再到结果验收的全流程**，为后续阅读、补全真实 PyTorch 代码（如 CNN、RNN、Transformer 架构）以及可能的交叉研究打基础。

## 二、核心设计决策

**1. 做减法，不做全能工具。** 舍弃硬件扩展、多语言模式切换等对通识教育无意义的功能，界面尽量简洁，只保留最基础、最核心的流程。

**2. 与主流 AI 框架逻辑对齐。** 生成的代码在结构上与 PyTorch 一致，学生后续面对真实代码环境时无需经历范式转换。目标是让学生能读懂并补全教材中的经典架构代码，而非仅留下模糊印象。

**3. 给“完美代码”，不刻意模仿手写风格。** 在 AI 辅助学习成为常态的当下，直接提供结构清晰、命名规范、注释得当的 PyTorch 代码，学生的认知负担更低。他们需要的是读懂代码的能力，而非先手写一遍。

**4. 底层高亮建立积木与代码的映射。** 学生拖拽积木时，实时看到对应代码行的高亮。代码展示是可选的——默认隐藏，供想进一步探索的学生开启。脚手架代码（如 `super().__init__()`）保持低亮，点击时给出解释，既不掩盖真实代码的完整面貌，又不让高亮信息过载。

**5. Tutorial 承载交互式知识传授。** 讲解基础知识的同时，嵌入算子可视化演示和参数实验，让学生在做中学。

**6. 面向小白的傻瓜式设计。**要时刻假设使用者缺乏最基础的计算机常识，因此，一切都要尽量用最简单的语言说明。并且尽量简化软件常见的 **setting**、**file** 等设置选项，即使绕不开，也尽量用简单的语言说明每一个选项的作用与功能范围。

**7. 错误处理的提示机制**。资深程序员与小白最大的区别在于：程序员可以读懂程序的报错，甚至可以直接根据程序行为反推出程序的错误。最直接的体现就是：资深程序员很少被 “这里没大写” 困住，但这个问题可以困扰小白一整天。因此，即使在错误处理方面，也要给用户尽可能详细且可靠的提示。更重要的是：是否可以通过一些机制，降低用户出错几率。

## 三、与现有产品的差异

| 维度          | LayerStudio / Natch | ML Forge       | 你的设计                         |
| ------------- | ------------------- | -------------- | -------------------------------- |
| 交互范式      | 节点图 / Blockly    | 节点连线       | 类 Scratch 积木拖拽              |
| 覆盖范围      | 仅模型定义          | 数据+模型+训练 | 数据读入→训练→验收全流程         |
| 代码生成      | 仅 `nn.Module` 子类 | 完整 train.py  | 完整可运行 PyTorch 代码          |
| 教学交互      | 维度验证            | 无             | Tutorial + 算子可视化 + 参数实验 |
| 积木↔代码关系 | 静态展示            | 无             | 动态高亮映射                     |

## 四、一句话概括

**用类 Scratch 积木拖拽完成 PyTorch 全流程训练，以算子可视化支撑交互式教学，以动态高亮建立积木与真实代码的对应关系，让非编程专业本科生在通识课程中真正读懂 AI 的计算逻辑。**
